# Internationalization SSoT

**状态**：已确认，待实现（2026-08-18）  
**首发语言**：`zh-CN`, `en-US`

## 1. 目标

Ensemble 从首版开始使用可扩展的多语言架构。UI 语言、用户输入和 Agent 输出是三个不同概念，不得混用。

| 内容 | 所有者 | 是否翻译 |
|------|--------|----------|
| 按钮、菜单、状态标签 | Canvas UI | 使用 locale key |
| Runtime 系统事件 | Runtime 提供稳定 code/key | UI 翻译 |
| 用户输入 | 用户 | 原样保留 |
| Agent 输出和 Artifact | Runner / Agent | 由 Run 输出语言控制 |
| 技术 ID、路径、命令 | 系统 | 不翻译 |

---

## 2. Locale 配置

设备偏好：

```json
{
  "uiLocale": "zh-CN"
}
```

Run 配置：

```json
{
  "outputLocale": "zh-CN"
}
```

规则：

- `uiLocale` 控制产品界面
- `outputLocale` 控制 Agent 提示和期望输出
- Workspace 可以保存默认 `outputLocale`
- Run 启动时冻结其 `outputLocale`
- 修改 UI 语言不能改变运行中的 Agent 输出
- 未显式选择时，Workspace 默认输出语言可以取创建时的 UI 语言

---

## 3. 翻译资源

所有 UI 文案使用稳定 key：

```text
workspace.create.title
run.action.start
run.status.waitingForYou
seat.inspector.outputs
attention.action.requestChanges
```

禁止：

- 在组件中拼接可见句子
- 使用英文文案作为翻译 key
- 将内部枚举直接显示给用户
- 通过判断当前语言改变业务逻辑
- 在同一界面中混用两种 UI 语言

翻译缺失必须在构建或测试阶段失败，不允许上线后静默显示 key。

---

## 4. Runtime 消息协议

确定性的系统消息使用：

```json
{
  "message_key": "attention.reviewApprovalRequired",
  "message_params": {
    "seatName": "Reviewer",
    "artifactName": "patch.diff"
  }
}
```

事件仍必须提供稳定业务字段，例如：

```text
status=waiting_attention
action=approve
node_type=gate
```

`title`、`body` 等自然语言字段仅用于用户或 Agent 生成内容。Runtime 自身不得写死英文审批标题。

---

## 5. 格式化

以下内容统一通过 `Intl` 或等价标准能力：

- 日期和时间
- 相对时间
- 数字和百分比
- 文件大小
- 列表连接
- 复数

后端传输 ISO 时间、数值和稳定单位，不传已经格式化的本地化字符串。

---

## 6. 布局约束

- 按钮和 Tab 不依赖固定文案宽度
- 允许文本较英文扩张至少 30%
- 长文本优先换行，其次截断并提供完整内容
- Seat 的动态文案不能改变节点整体尺寸
- 检查器和菜单在两种首发语言下不得横向滚动
- CSS 使用逻辑方向属性，避免把语义写死为 left/right
- 首版不承诺 RTL，但结构不得阻断后续支持

---

## 7. 字体与输入

- `zh-CN` 必须具有明确中文字体回退
- `en-US` 使用同一 UI 字体的拉丁字符集
- 等宽字体只用于技术内容
- 输入法组合期间不得触发快捷键或提交
- 搜索、命令面板和画布快捷键必须正确处理 IME

---

## 8. 验收

- `zh-CN`、`en-US` 全流程截图
- 伪语言扩张测试
- UI 中无直接显示的内部枚举
- Runtime 确定性消息无硬编码英文
- 同一 Run 在不同 UI Locale 下业务状态一致
- `outputLocale` 能传递到 Runner，并写入 Run 元数据
- 日期、时间、数字使用当前 Locale 格式
